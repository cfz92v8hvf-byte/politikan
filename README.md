# Политикан — редактор европейских новостей для Telegram

Бесплатный MVP для русскоязычного Telegram-канала: забирает новости из RSS, исключает дубли, переводит их, создаёт очередь и публикует после редакторского одобрения.

## Что уже умеет

- читает утверждённые RSS-ленты;
- принимает только свежие материалы (по умолчанию до 6 часов);
- удаляет дубли по ссылке и похожим заголовкам;
- переводит заголовок и краткое описание через настраиваемый LibreTranslate-совместимый API;
- сохраняет очередь в SQLite;
- публикует в канал пост с источником и ссылкой на оригинал;
- поддерживает `review` (только очередь) и `auto` (автопубликация) режимы.

На старте используйте `review`. Для политических новостей публикация без проверки — риск ошибки перевода, контекста или непроверенного сообщения.

## Бесплатная архитектура

`RSS → scripts/run.py → SQLite/очередь → Telegram Bot API`

Планировщик — GitHub Actions. Он бесплатен для публичных репозиториев; в частных есть ограниченный бесплатный лимит. Запуск по расписанию может задерживаться, поэтому это не система реального времени. Переводчик задаётся переменной `TRANSLATOR_URL`: можно подключить свой LibreTranslate или бесплатный API с подходящими условиями. Не храните токены в файлах.

## Быстрый запуск

1. Создайте Telegram-бота через `@BotFather`, добавьте его администратором канала с правом публикации.
2. Скопируйте `.env.example` в `.env` и заполните `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHANNEL`.
3. При необходимости задайте `TRANSLATOR_URL` и `TRANSLATOR_API_KEY`.
4. Выполните:

```bash
python3 scripts/run.py
python3 scripts/review.py list
python3 scripts/review.py approve 1
python3 scripts/run.py --publish-approved
```

Без переводчика новые записи попадут в очередь с английским заголовком: это намеренная защита от публикации некачественного машинного перевода.

## Настройка облачного запуска

В GitHub добавьте secrets: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHANNEL`, `TRANSLATOR_URL`, `TRANSLATOR_API_KEY` (последний — если требуется). Затем включите workflow `.github/workflows/hourly.yml`.

Расписание сейчас: каждые 5 минут после начала часа. Время GitHub Actions — UTC; Москва опережает UTC на 3 часа. Его можно изменить в workflow.

### Редакторский процесс

1. Каждый час workflow наполняет очередь.
2. Вы просматриваете её в удобное время через `scripts/review.py list` или будущую веб-панель.
3. Одобряете подходящие посты и запускаете публикацию. После периода проверки можно переключить `mode` в `config/settings.json` на `auto`.

## Контент и права

Посты используют краткое изложение, название источника и прямую ссылку на оригинал, а не перепечатку статьи. Перед постоянной работой подтвердите условия использования каждого RSS-источника и права на изображения. По умолчанию изображение не копируется: это безопаснее; поддержку разрешённых изображений добавим отдельно.

## Операционные правила

Для любых изменений в Telegram действуют обязательные проверки:

1. До сохранения сверять название целевого поля и полный вводимый текст.
2. После сохранения проверять настройку на экране канала и, для публичной ссылки, открывать её отдельно.
3. Боту выдавать только право публикации; остальные права отключать.
4. Не менять несколько независимых настроек одним действием и не продолжать после ошибки интерфейса без повторной проверки состояния.
